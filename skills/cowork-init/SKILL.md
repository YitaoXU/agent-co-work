# Initialize a project

Read [cowork](../cowork/SKILL.md) for the collaboration rules. The user never runs `cw` or Python; the coordinator shows the plan and runs the commands after confirmation.

Use the public release `https://github.com/YitaoXU/agent-co-work.git` at `~/.agent-co-work`, one fixed clone per machine shared by all target projects. HTTPS needs no GitHub key for the public repo; a private repo needs the user's normal GitHub credentials. Existing clones retain their origin.

1. Work from the target project's root in the coordinator's Herdr tab, with `HC_TERMINAL_ID` and its `herdr.space` label set. Use normal permissions outside the sandbox for release-clone access, CLI discovery and `hc` during apply. For an existing install, follow Upgrade below. For a new project, run `git clone https://github.com/YitaoXU/agent-co-work.git ~/.agent-co-work` if missing; otherwise `git -C ~/.agent-co-work pull --ff-only`.
2. Before proposing seats, probe `command -v claude codex agy` outside the sandbox (sandbox PATH may omit `~/.local/bin`). Discover installed models with `agy models`, `codex debug models`, and Claude's model aliases (`claude --help`: `fable`, `opus`, `sonnet`, or a full name). Build a recommended table only from installed CLIs, including `discussion`; offer Claude-only, Codex-only or agy-only presets when appropriate. Preserve each role and lifetime. Warn if any requested row requires a missing CLI.
3. Show the recommendation, then ask one question with two options: keep all defaults / adjust seats. If adjusting, ask one question per seat with two options: its recommended default (for example `codex gpt-6-astra high long`) / type your own `agent model effort [life]`. List discovered valid values; adapters are `claude|codex|agy`, life is `short|long`. A Claude coordinator uses its multiple-choice question tool, at most four questions per call; other coordinators ask the same questions in chat. Finally show and confirm the complete table before applying.
4. Efforts: Claude lists `low`, `medium`, `high`, `xhigh`, `max`. agy lists the same efforts, but its model name also carries effort (e.g. `gemini-4-neon-xhigh`); choose a matching pair from `agy models`. Codex efforts depend on the model: use `codex debug models`, not a global guessed list. Do not offer `ultra`, which delegates to sub-agents. Mark values not listed by the local CLI unverified, and refresh probes when versions change. Keep these choices in skills, not CLI validation code.
5. Run `python3 ~/.agent-co-work/bin/cw init` with repeated `--seat seat=agent:model:effort:life` for the chosen overrides (exactly four fields after `=`; no args field). Show the table, file plan and `kit: to <sha>`. Fresh init adds missing `cowork/`, `output/`, `.scratch/`, `.tmp/`, and `.worktrees/` ignores. Check warn-only init messages about dirty kit files or development checkouts. Apply that exact command with `--apply` only after confirmation. Configure optional args afterward with `cowork/cw seat set --args='...' <seat> <agent> <model> <effort> [life]`; never set `-a never` seat-wide.
6. Inspect `cowork/seats.tsv`, pointers, the initial coordinator record and `cowork/kit-version`; run `cowork/cw lint` and compare its SHA with the plan. The stamp records the clone's full HEAD and actual origin URL (HTTPS credentials removed). Plain init preserves an older or missing stamp; only fresh installation and upgrade write it.
7. Optional server setup: ask for every placeholder in `~/.agent-co-work/templates/server.md` (`{host}`, `{server_root}`, `{branch}`, `{local_only}`, `{large_files}`, `{server_paths}`, `{hardware}`), including explicit empty lists. Hardware is unverified until probed outside the sandbox. Confirm the filled guide, then save it to `docs/server.md` (or the declared docs path); never overwrite an existing guide, review it instead. Add a pointer outside the marked block in `AGENTS.md`.
8. Use the user's `<project description>` (goal, current state, key folders/docs, first work) to prepare Direction and Plan through the core task loop. For a long effort, run `cowork/cw project new <name>`: it creates a plans README only when exact-case `docs/plans/` exists, the project folder is absent, and no `cowork-outputs:` layout is declared in `AGENTS.md`; otherwise it prints a note and leaves plans alone. Fresh init creates the root folder index and Brief template only without any existing plans folder; plain init and upgrade preserve them. Then prepare the first task with `cowork/cw new <task> --seat <seat> --kind task --project <name> --line main` and fill its Goal and Brief.

## Upgrade

1. When the user says upgrade, run `cowork/cw upgrade` (optional `--kit <dir>`; default `~/.agent-co-work`). It requires an existing install and clean release clone at a Git repo root, refuses development checkouts or missing kit files, and pulls with `--ff-only` before showing the clone's plan and SHA. Resolve any refusal before proceeding.
2. Show the plan and SHA. After confirmation, run `cowork/cw upgrade --apply` with the same `--kit` if used. It does not pull: it applies the clone as it stands and runs the newly installed `cowork/cw lint`. Keep the shared clone unchanged between plan and apply; if another project updated it, show a new plan before applying. Compare lint's installed SHA with the confirmed plan.
3. Upgrade refreshes the CLI, bundled assets, copied skills, kit stamp and marked `AGENTS.md` block. It preserves records, seats (including legacy names), the coordinator address, `.gitignore` and project text outside the block. Use [cowork-seat](../cowork-seat/SKILL.md) for seat changes. Length guidelines and duplicates warn; invalid schemas, headers or paths still fail.
4. If the installed `cw` does not recognize `upgrade`, bootstrap once with normal permissions outside the sandbox: `git -C ~/.agent-co-work pull --ff-only`, then `python3 ~/.agent-co-work/bin/cw init --upgrade`; show and confirm the plan, then run `python3 ~/.agent-co-work/bin/cw init --upgrade --apply` and `cowork/cw lint`. Subsequent upgrades use the short command. Do not clone over a missing or broken existing installation silently.
