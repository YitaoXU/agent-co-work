GitHub README README（中文）

agent-co-work

A multi-agent collaboration kit you install into any project folder. You agree the direction with a coordinator, approve each task and decide the hard questions; the agents dispatch, review, record and hand over by one shared set of rules.

一套装进任意项目文件夹的多 agent 协作工具。你和协调员商定方向、批准每个任务、裁决重大问题；其余的派活、审查、记录和交接由各个 agent 按同一套规则完成。

platform平台 macOS / Linux needs依赖 Herdr · Python 3.9+ · git agentsagent CLI claude · codex · agy

What it is made of由什么组成

hc (Herdr)

Persistent terminals. Each agent runs in its own tab, so you can switch over to watch or take over at any time.

持久终端。每个 agent 跑在自己的标签页里，可以随时切过去看或接手。

cowork/cw

One standard-library Python CLI for task records, approval gates, launches, reports, resource locks, handovers and consolidation.

单文件、只用标准库的 Python CLI。负责任务记录、批准关卡、启动、汇报、资源锁、交接和整理。

5 skills

cowork holds every rule; cowork-init, cowork-seat, cowork-consolidate and cowork-away cover install, seats and handover, consolidation, and away mode.

cowork 是唯一的规则来源；cowork-init、cowork-seat、cowork-consolidate、cowork-away 分别管安装、角色与交接、整理、离开模式。

Get started开始使用

You never run cw or Python yourself. Install Herdr, at least one agent CLI, python3 and git. In Herdr, click +, choose your project folder, and start your coordinator in the new tab:

你不需要自己运行 cw 或 Python。先安装 Herdr、至少一个 agent CLI、python3 和 git。在 Herdr 里点 +，选择项目文件夹，在新标签页里启动协调员：

claude

To use another CLI, type codex or agy instead. Then paste the coordinator prompt from the README and fill in your project description.

想用别的 CLI，把 claude 换成 codex 或 agy。然后粘贴 README 里的协调员提示词，填上项目描述。

  1. Install: confirm the recommended seat table, file plan and kit SHA.安装：确认协调员推荐的角色配置、文件计划和 kit 版本号。
  2. Daily work: agree Direction and Plan, approve each Brief, decide escalated questions, read the Wrap-up summaries.日常：定方向和计划，每个任务前批准 Brief，裁决上报的问题，看收尾摘要。
  3. Upgrade: say “upgrade”; nothing applies until you confirm the plan and SHA.升级：对协调员说“升级”，确认它给出的计划和版本号后才会应用。
  4. Discuss: ask for a discussion seat and talk with it in the tab it names.讨论：让协调员开一个讨论席位，切到它告诉你的标签页直接聊。
  5. Away: say roughly how long you will be gone, answer its questions, say go; read the summary when you return.离开：说大约离开多久，回答它的问题，说 go；回来后看摘要。

Seats角色

Any seat can run any supported CLI; agent, model, effort and lifetime live in cowork/seats.tsv, and one task can override its agent.

每个角色可以运行任意一个支持的 CLI，模型、推理强度和生命周期写在 cowork/seats.tsv。单个任务也可以临时换 agent。

How a task runs一个任务怎么走完

  1. Direction: you and the coordinator agree what the project should become.方向（Direction）：你和协调员商定项目要做成什么。
  2. Plan: the coordinator lists numbered tasks, consults the advisor when useful, and records your approval with a date.计划（Plan）：协调员列出编号任务，需要时请顾问审阅，你批准后记一条带日期的决定。
  3. Brief: before each task, numbered steps, done-conditions, defaults and stop conditions; cw start refuses until you approve.Brief：每个任务开始前，协调员写好步骤、完成条件、默认值和停止条件，你批准后才能 cw start。
  4. Run: the coordinator dispatches steps and settles routine questions; science, scope, budget and risk questions come to you first.执行：协调员派步骤、处理小问题；科学、范围、预算、风险类的难题先问你再继续。
  5. Wrap-up: a short conclusion-first summary (result, evidence, lessons, next, decision needed); you decide what follows. Decisions sit in a bold ▶ block; a finished task with nothing left for you closes on its own.收尾（Wrap-up）：结论优先的短摘要（结果、证据位置、经验、下一步、需要你决定什么），由你决定接下来怎么走。待你决定的内容放在加粗的 ▶ 块里；已完成且没有待你决定事项的任务自动关闭。

Approved tasks can run in parallel. Long or multi-task Briefs live in docs/plans/<project>/NNN-* (_misc without a project); short ones stay in the task record. The root README indexes project or line-of-work folders and keeps the Brief template alongside it. Each folder has a README and may contain subfolders; numbering is per folder unless the parent README declares it shared. Declared AGENTS.md layouts take precedence.

多个已批准的任务可以并行。长的或跨任务的 Brief 放在 docs/plans/<project>/NNN-*（无项目用 _misc），短的留在任务记录里。根 README 索引项目或工作线目录，Brief 模板也保留在根目录。每个目录各有 README，可继续设子目录；编号按目录独立，除非父 README 声明共用。AGENTS.md 已声明的布局优先。

Workers and auditors never commit; the coordinator commits after acceptance, with explicit paths.

执行者和审计员从不提交代码；协调员验收后按明确路径提交。

A Brief-named output path wins. The default project comes from the task, then its parent, else _misc (project names contain no underscore). Declare cowork-outputs: <template> outside the marked AGENTS.md block using {project}, {yyyymmdd}, {task}; e.g. output/{yyyymmdd}/{task}/. Use _misc only where the layout names no folder for project-less work. Launch prompts show the main-checkout default via COWORK_ROOT. Existing outputs and plans never move; old citations stay valid.

Brief 指定的输出路径优先。默认项目依次取任务、父任务的 project，否则用 _misc（项目名不含下划线）。可在 AGENTS.md 标记区块外写 cowork-outputs: <template>，使用 {project}、{yyyymmdd}、{task}，例如 output/{yyyymmdd}/{task}/；仅当布局未另行指定无项目任务的目录时使用 _misc。启动提示通过 COWORK_ROOT 显示主 checkout 默认路径。已有输出和计划不搬动，旧引用继续有效。
